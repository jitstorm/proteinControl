# 一、当前确定的整机制作顺序

按现有机械设计，制作主流程为：

1. 机械臂复位 / Home
2. 去搅拌器清洗位置
3. 打开清洗/抽水水泵
4. Z 轴上下运动，清洗搅拌器
5. 关闭清洗水泵
6. 去取杯位置
7. 落杯器落杯
8. 根据订单/配方执行原料流程

   * 水
   * 粉料
   * 以及已经明确存在映射的其他配方通道
9. 去出杯/门位置
10. 执行落杯
11. 执行落盖
12. 正常结束制作

不要自行加入目前没有明确需求的动作。

尤其不要自行增加：

* 自动加热流程
* 自动开门/关门的新逻辑
* 自动搅拌步骤
* 果浆位置
* 粉料 5/6
* 新传感器
* 新设备 ID

除非现有工程已经明确存在这些业务定义。

这里：

不要求 homed
不要求 position_valid

因为下一步就是 Home。

# 十一、水泵必须 finally 关闭

这是安全要求。

清洗结构必须类似语义：

pump ON

try {
cleaning Z movement
} finally {
pump OFF
}

无论：

* Z LIMIT
* RobotArm timeout
* Driver error
* MachineProcess cancel
* Exception

都必须尽最大努力发送：

pump OFF

不能出现：

机械臂失败
→ 水泵一直开

如果现有 MachineProcess 有 cleanup / compensation 机制：

优先复用。

否则为设备动作补充最小的 finally-cleanup 能力。

不要为此重写整个流程引擎。
