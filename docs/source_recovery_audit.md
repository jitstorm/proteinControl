## 3. 四个受损文件的语义对比

### `User/main.c`

恢复副本保留：系统时钟、延时、595/165、SPI、TIM2/3/4、TIM5/PB11、TIM6/PB10、USART 初始化；主循环中的串口处理、温度、命令、PB10 完成上报、165 扫描、旧限位与超时任务。

与 Git `e73934e` 及当前模块调用关系相比，已确认缺失：`SingleMotor_Init()`、`ReversibleMotor_Init()`、`task_single_motor()`，以及主循环中新架构的相应调度。恢复前当前版本还显示 `Stepper2_Init()` 包装入口；恢复副本退回为 `stepdma_pb10_init()`。

状态：**已确认丢失**（新模块文件仍存在但没有可靠初始化和任务入口）。

### `User/protocol.c`

恢复副本保留旧协议分支，包括 0x00、0x01、0x03、0x04、0x05、0x06、0x07、0x11、0x13..0x1F、0x20，以及 0x1B/PB11、0x1C/PB10、0x1F/PB10 状态查询。

发现两个同名 `handle_command()` 定义和两组重复 `case`：前一组仍含多项旧命令，后一组是较新的单向电机分发但仅覆盖部分命令。C 语言中同名外部函数重复定义将导致链接/编译失败；即使屏蔽其中之一，也可能让旧协议覆盖新的单向/正反转/状态协议。与 Git `e73934e` 相比，当前恢复本缺少 `case 0x02` 的已停用标记，且尚不能确认 0x09..0x0C 新正反转协议是否完整保留。

状态：**已确认丢失**（单一、完整的最终分发器）；**疑似旧协议覆盖**（重复分发器）。

### `User/step_dma.c`

恢复副本保留两路 DMA 步进：

| 轴 | STEP | DIR（恢复副本） | 定时器 / DMA | 已保留行为 |
| --- | --- | --- | --- | --- |
| PU1/X | PB11 | 需以最终协议为准；文档记录第二片 595 bit4 | TIM5 / DMA2 Ch2 | BSRR 高低交替、2 edge/step、Normal 分块、梯形、DMA TC、停止拉低 |

状态：**已确认丢失**（完成上报状态与接口）；**疑似丢失**（最终 PU2 DIR 映射）。

## 4. 协议功能基线（审计结论）

以 `readme` 和 Git `e73934e` 为当前可验证基线：

- 0x05/0x06/0x07/0x08：19 路单向电机的即时、定时、传感器/超时、状态位图；
- 0x09/0x0A/0x0B/0x0C：五路正反转电机的即时、定时、传感器/超时、状态/停止原因；
- 0x1B：PB11 DMA 步进；0x1C：PB10 DMA 步进；0x1F：PB10 状态/完成；0x20：PB10 传感器停止；
- USART 接收应经队列/环形缓冲，在主循环解析；发送区分 ACK 与主动事件；
- 595 改位必须保留同片其他位并使用 `ShiftRegister_WriteAll(HC595Data)`。

当前恢复副本不能证明以上所有项均被保留，尤其是 0x09..0x0C、单向电机任务、PB10 完成上报和最终 DIR 映射。

## 5. PU3 前置资源审计

工程配置为 STM32F103RE、`STM32F10X_HD`，启动文件有 `TIM7_IRQHandler` 和 `DMA2_Channel4_5_IRQHandler` 向量。PU3 已使用 TIM7、DMA2 Channel4 与 `DMA2_Channel4_5_IRQHandler`；旧 `stepMotorB` 及其 PB13 引用已删除。

尚未以目标板实测或芯片参考手册的 DMA 请求表确认 “TIM7_UP -> DMA2 Ch4” 的合法性；因此 PU3 仍不能视为已完成硬件验证。
